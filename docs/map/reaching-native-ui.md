# Reaching an app's native UI

How `native list`, `native choose` and `native answer` read and operate a launched app's menu bars and dialogs on Windows. Code: `native::menus`, `native::choose`, `native::dialogs`, `native::answer`, `native::clean_label`, `native::button_matches` (native.rs), `State::native_*_cmd`, `State::keep_foreground_after` (session/native.rs), `launch::keep_foreground`.

## Design model

- **Menu bars are read and chosen through Win32, not UI Automation.** Tauri's menus (muda 0.20.0) are ordinary Win32 menus: `CreateMenu` and `SetMenu` build them, and a click arrives as `WM_COMMAND` with the entry's id (`muda` `platform_impl/windows/mod.rs` 245, 280, 1051). pokit reads the tree with `GetMenu` / `GetMenuItemInfoW` without opening anything, and chooses an entry by posting that `WM_COMMAND`. So it needs no focus and opens no menu. A disabled entry, or an entry that only opens a submenu, is refused (exit 1); a path no menu has is not found (exit 5). **Maintainer's call (2026-10-06, #5):** menus through Win32, dialogs and reading through UI Automation. The alternatives shown were all UI Automation, which opens menus and so needs the window in front, and all Win32, which cannot read custom-drawn UI or the file dialog.
- **Labels are shown as the user sees them.** The `&` access marks are dropped (`&&` stays `&`), and the shortcut after a tab is split off: `Say &hello\tCtrl+H` is listed as `Say hello (Ctrl+H)` and chosen as `File > Say hello`.
- **Dialogs are the app's `#32770` windows, read through UI Automation.** Their text and buttons come from the element tree; buttons in the title bar, such as Close, are left out.
- **A Win32 button is pressed by posting the dialog the `WM_COMMAND` its click sends.** UI Automation's Invoke on a Win32 button sends `BM_CLICK`, which "might fail" when the dialog is not active (`BM_CLICK` remarks, win32 docs, read 2026-10-06). The fix those docs give, `SetActiveWindow`, would take the user's focus. Measured: pressed as soon as the dialog appeared, Invoke left it open 4 times out of 5, and the posted `WM_COMMAND(id, BN_CLICKED)` closed it 5 times out of 5 (2026-10-06). Buttons of other kinds still go through Invoke. Before pressing, pokit waits until the dialog's thread takes a `WM_NULL` (`SendMessageTimeout`, 1 s). Afterwards it reports `closed`, from whether the dialog's window is gone within 1 s. A button that does not close its dialog is not pressed again.
- **A localised button answers to its name without the access key.** On a Korean system the fixture's buttons are `예(Y)` and `아니요(N)`, and `native answer 예` presses the first. `native list` gives the full names.
- **What pokit sets off in the app does not keep the foreground.** A dialog activates itself when it opens, and the app regains the foreground when it closes, both with the right inherited from the terminal in front ([[launching-a-test-instance]]). Measured 2026-10-06: after `native choose "Help > Ask"`, the fixture held the foreground for about 2.1 s. So for 2 s after `native choose` and `native answer`, the session gives the foreground back whenever the app takes it, as it does during `launch`; after that change the fixture never showed up in front. *Derivation, not a maintainer's call:* this extends the launch give-back the maintainer chose (#1 story 42) to the native commands, with the same best-effort limit.
- **An attached session cannot reach the native UI** (exit 7). It does not know the app's process, and the native UI is found by process.
- **Not covered yet:** context menus (muda calls `SetForegroundWindow` before `TrackPopupMenu`, so they need the app in front), the tray, and the file dialog. They wait for #5's activation command.

## Testing

- `tests/native.rs` takes button names from `native list`, because they follow the system's language.
- `a_dialog_the_app_opens_does_not_keep_the_foreground` only tests anything when it descends from the foreground app (`window::can_take_foreground`). With the terminal's window owned by a sibling process of the shell's ancestor, it returns; a mutation removing the give-back after `native choose` could not be tried that way (2026-10-07).
